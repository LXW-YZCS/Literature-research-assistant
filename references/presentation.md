# 科研汇报制作

## 参考模板的解释与内容适配

制作前区分三类信息，不把整份历史模板视为当前硬约束：

- 通用质量要求：文献依据准确、贡献归属明确、机制解释充分、图文对应、讲稿一致、可读且可编辑。这些要求持续适用。
- 当前任务约束：用户针对本次明确要求的文献范围、受众、时长、必须的页数或格式。仅在本任务有效；用户明确给出的要求不能因曾有参考模板而被忽略。
- 参考与示例：模板中的占位文献名、示例页数、建议章节、历史配色和过往案例。用户说明模板供参考时，不能自动将11—12页、15分钟、石墨紫、两篇文献或固定页序设为所有任务默认值。方括号本身不证明是占位符，应结合用户对模板的定位判断。

用户提供旧要求并复盘其问题时，任务是讨论或完善规则，不是重新执行旧模板中的PPT制作命令。用户当前明确说“严格12页”时遵守；说“参考这个框架，页数按内容”时由内容决定，不反复询问已明确的选择。

选页顺序：先确定研究问题与核心贡献 → 识别理解方法必需的知识和图解 → 选择支持结论的实验证据 → 根据时长确定详略与页面。不能先固定页数再填内容。一页一个问题允许必要的多个证据与解释单元，不能执行成一页一句空泛结论。篇幅超过时长时优先收敛范围、压缩次要背景，不能一味增加页数或缩小字体；不足时合并，不用空泛页面凑数。必要时给出所选页数的简短理由，不要求用户审批普通排版选择。

背景只铺垫听懂核心方法必需的概念，重复的问题预告、路线比较与目录应合并；尽早进入具体机制。核心页优先回答困难、现有方法为何不够、处理手段为何有效及其代价，用连续示例连接定义、推理、约束与结论；不要将“问题—不足—方法—效果—代价”当作每页固定标题格式。区分论文借用的既有框架与本文新增贡献，讲稿与正文均避免“作者先做A、然后B、最后C”的动作罗列。

内容解释是首要验收目标：让有基础但不熟悉论文的听众明白研究为什么这样设计、图中的比较如何支持发现、关键变量和不同结果如何关联。先建立面向听众的论证与讲解，再选择适配版式；不能用漂亮模板或页面填充率替代解释。正文给出可见证据与必要术语，讲稿补充因果、读图和承接，用真实汇报者的自然中文表达，不照搬页面、不念审查清单。

核心方法讲清输入、约束、关键状态变化及为何减少计算。具体例子应确实符合论文模型，可优先用于讲稿帮助解释；正文应优先呈现论文的实际机制与证据，不默认安排连续独立教学示例页。确有必要时可在相关页面嵌入简短例子，用户明确要求展示时遵从；教学设定与作者实验要分清。结果要解释基线、条件、差异及相应成本；研究方向先与论文已有机制逐项对照，再提出具体待验证变化。听众应能复述研究问题、理解关键机制并解释主要实验；内容因果比页数、术语数量与公式数量更重要。

建议结构是可选模块，不是必须逐项独立成页。原创算法、理论分析、系统实现、实验研究与综述，应根据其证据类型调整方法、推导、系统图、比较和实验的比例。没有实验数据时不强造结果页；没有第二方案时不强做比较页。

完整论文汇报可按论文需要选用封面、科学问题、研究思路、数据或样本、方法、若干核心结果、机制与发现、创新、具体局限、启发及可选参考文献。结果是重点，背景压缩到理解方法所需；不同学科不适合的样本、机制或固定数量结果不强造。每页尽量围绕一个核心结论，结果页优先用被该页证据直接支持的学术结论型标题；不固定句式，也不将所有页面机械改成结论句。

完整论文PPT在读完论文并查看模板后、开始制作前，向用户展示预计页数和逐页表：标题、主要内容及拟用Figure / Panel；无需图的页面标“无／示意图”，未核实的不编图号。接着直接制作，不将安排变成审批节点；除非用户明确要求先确认，或仅请求大纲。实际制作中根据文献和可读性调整后，保持最终页面、讲稿与来源一致。

版式依据内容功能选择：原文图与机制解释、算法步骤与输入输出、推导与符号说明、实验设置与结果分析等。禁止将某一成功页面、三列卡片、固定表格或底部总结复制到每页；正文信息密度与投影阅读共同决定布局。

“可以先给配色预览”表示选项，不是每次的前置审批。只有用户明确要求先看方案、再选风格时才执行该阶段；否则使用当前指定样式或参考稿合理完成。不得因长期默认样式覆盖本次明确要求。
## 设计流程入口

制作或修改演示文件时读取 [页面设计与模板学习](slide-design.md)，先形成逐页任务与证据安排，再选择布局；仅写大纲或讲稿时按需参考内容组织与表达部分，不启动应用编辑。该文件集中维护参考提炼、模板搜索、内容密度、文案、素材、编辑性和样页检查规则。

## 每次制作

1. 读取 [偏好档案](preferences.md)。如果用户给了旧稿或参考 PPT，区分它是内容来源、设计模板还是待修改对象。需要制作或编辑演示文件时，同时使用可用的 Presentations skill 及其当前工具规范。
2. **先分析并总结文献，再决定页面。** 阅读原始论文和指定资料，形成可追溯的内容梳理：研究问题、既有方法不足、作者方法、实验设计与结果，以及具体模型条件和实验范围。记下关键论断对应的图、表、公式、条件或页码。区分作者结果、综述转述、汇报者推理和教学示意；无法核实的数字或机制不要写成事实。核对判断转化为自然的科研表达，正文和讲稿不照搬内部审查用语。
3. 明确本次汇报主问题和范围，分清核心论文、辅助论文、背景概念与上次遗留问题各自承担的作用。按论证逻辑决定页序和篇幅，避免让多个主题并列争夺主线；每页回答一个明确问题，并说明它与前后页的关系。
4. 方法页要解释**如何实现**：输入、关键步骤、约束条件、输出，以及它承接上一页什么问题、下一页将验证什么。关键术语和符号在首次使用时定义；不能用算法名列表代替机制解释。
5. 实验结果是重点：说明研究动机、实验方法、比较对象、指标、图的坐标与图例、主要发现及其研究含义，帮助不熟悉该方向的听众读懂，而不只是粘贴Figure。保留结果间的逻辑联系，每页尽量围绕一个核心结论，优先使用与证据一致的结论型标题。比较多篇论文时先确认任务、假设和指标是否可比。
6. 讲稿依赖图才能理解的内容，页面上必须有对应依据。插入原文图时解释其坐标、变量、曲线差异与它如何支持结论；原文图不足以解释时，补充清楚标注的概念示意，并与论文实验结果区别。新增概念先铺垫和定义，术语全篇统一。讲述者的推理和后续研究想法应标为自己的分析。
7. 视觉结构服务于内容：依据机制、算法和实验证据选择不同布局，控制每页信息密度；不要机械复用表格与底部总结，也不要用留白或大字号掩盖信息缺失。公式与符号保持可读、一致和必要；不明符号先查原文。
8. 导出或渲染后按 [逐页验收](review.md) 同时检查内容、视觉和口头讲述。讲稿在最终页面调整后同步修订，讲图位置、术语和解释顺序必须一致。优先修复已发现的缺陷，减少无谓的多版本重做。若用户只要文献分析、大纲或评审，不主动扩展为完整 PPT。


讲稿以论文原文及相关图表、当前最终页面、已完成且可追溯的分析、听众背景和已知时长为输入；材料缺失时先核实，不将页面扩写冒充论文分析。核心页选出听众最需理解的问题，解释必要推理、比较设置与结果；区分整套方法比较、设计作用分析和消融实验。封面或过渡页可简短，不固定每页结构或字数。完整讲稿在已知时长时给出大致时间分配。

逐页提供可直接朗读的独立口播，默认不写入PPT备注；仅当次明确要求时才写备注。面对听众用自然、通俗而准确的语言解释对象、原因和关键结果，避免逐个念长小数或表格数据；必要的代表性数字可采用忠实原意的近似表述，精确值留在页面或备答。确有需要时另列讲者提示或备答，来源定位与制作提醒不进入口播。若把内容写入PPT备注并用于 `prepare_speech_notes.py`，口播置于开头，可选单独一行“口播正文：”；随后各非口播区域以独立一行“讲者提示：”“备答：”或“资料定位（非口头讲稿）：”开始，后续内容不作为口播。学习笔记、PPT与讲稿分别承担理解、展示与口头解释的任务，不能直接互相复制。页数根据时长与内容决定，不继承某次任务的固定页数或配色。用户只要求某一页或文字时，仅完成该范围。

## 应用执行与已确认风格

默认通过前台WPS可视化逐页执行，与独立cli-anything-wps协作；读取[执行规则](../../cli-anything-wps/references/ppt-policy.md)。2026-10-31用户已撤销固定居中大标题、字号、页数、间隔和评分门槛等历史样式。具体字号与布局由本稿内容及投影阅读决定，按slide-design.md先验证代表性页面。

## 图形后端与素材

需要SVG制作或转换时读取 [SVG流程](svg-pipeline.md)；需要按数据制图、寻找图片或背景时读取 [图表与素材](charts-and-assets.md)。前台执行以visible-authoring.md为准。独立SVG素材可以后台准备，再在WPS当前页插入和排版；后台生成整套PPT只在用户当前明确指定时启用，不沿用历史授权。

## 正文与制作记录分离

检索策略、选图理由、版式决策、工具执行、质量核查及助手自我评价只写入内部工作记录，不进入PPT正文，也不自动转入讲稿。正文呈现研究问题、论文方法、必要推导、实验设置、数据证据与科研结论。使用论文原图的每页在对应图片下方居中标注Figure / Panel与简短文献出处；多图分别居中或共享组合图注。背景外部图片标注可靠来源，详细定位和素材记录放备注资料区及工程清单。图注不做成每页重复的灰色页脚。交付前检查并移除制作说明与泛泛的防御话术，保留论文中有依据的科学内容。

图注默认简洁标注文献及 Figure / Panel，不默认加入“根据……重绘”“局部重绘”等制作过程说明；图形来源与重制方式在备注或工程清单如实记录。若出版要求或用户特别要求说明改编，按要求保留必要标记，不得将修改后的数据冒充原图。

完整执行入口见 [presentation-workflow.md](presentation-workflow.md)，图旁呈现必要图号与文献，详细定位进入备注资料区或工程清单，不进入口头讲稿；制作与检查记录只在工程目录保存。
