# 科研演示完整执行流程

仅在演示制作与修改时启用。研究助手负责材料、论证、科研准确性和用户偏好；显式使用 SVG 转换等功能时，可选用单独安装的 ppt-master 后端。完整论文汇报默认逐页讲稿并展示逐页安排后直接制作。用户直接指定独立 ppt-master 时使用其对应入口；不得伪造工具通过记录。

## 1. 材料与论证

先按reading.md阅读全文，记录关键图表、公式、实验参数与结论位置。文献是事实来源，外部检索只补当前任务需要的背景。先确定听众、时长与核心研究问题，形成逐页任务，不把论文目录机械转换为页序。

完整新稿用`scripts/research_deck.py init <project>`建立内部工程；填充`research-deck.json`。局部编辑使用现有工程。字段示例：
```
authoring_mode: wps
presentation: exports/report.pptx
sources: [{id: paper, path: sources/paper.pdf}]
pages: [{id: p01, role: method, claim: 本页具体发现,
         evidence: [{source: paper, locator: Fig.3 / p.5}],
         slide: 1, expected_title: 当前页标题}]
assets: [{path: images/device.png, role: context-image,
          source: https://来源页面, rights: 许可或使用依据}]
```
此示例解释JSON字段，实际文件使用合法JSON；教学数据登记为demonstration来源。清单只存来源和制作决定，不存逐步思维过程，不进入幻灯片或讲稿。

## 2. 模板与版式

按slide-design.md查看参考并提炼统一风格和多种页面结构。已有原生PPT模板时通过`ppt_backend.py import-template -- --help`确定导入参数；复用模板工作区按上游`workflows/stages/apply-template-workspace.md`和`references/strategist-template.md`执行。适配器提供import-template/apply-template/register-template/template-preview入口，不将一次截图分析冒称为已注册模板。

当次借鉴风格可直接在设计记录保存配色、字体、间距、页面角色与示例布局。只有要求跨任务保存模板时才注册到指定库；不能将论文实验数据保存在通用模板。视觉层级、色彩可复用，标题尺寸与正文图表按内容调整；不继承上游示例固定字号和间距。

完整重做或新论文任务不得直接运行旧稿生成脚本、简单替换路径或颜色后作为新设计；旧稿和代码只作为可核对的参考。先依据本次论文的机制、图表和听众，实际查看候选模板正文页，决定是直接适配整套、使用其具体页面的信息组织，还是按需组合；记录实际借鉴的页面结构、图文关系与需要修改之处，而非只记录颜色和标题栏。可复用与论文无关的安全操作和排版组件；当次脚本或页面配置必须由当前内容驱动，不能把某篇论文的页序、标题、图号、分类小字、固定版式或结论条固化为未来默认。

制作每页前，用简短工作记录衔接本页问题与证据、候选模板名称和页码、是否实际看过及其结构、图文区域与阅读顺序、拟保留或调整的对象及理由；直接供当前页制作使用，不进入正文，也不要求固定表格。检索仅得到候选：只有实际查看并判断区域比例、关系线含义及图表复杂度后才能选用；不适合时重组、换页或自行设计。复用前检查目标应用里的原生对象，无法复用时记录并按结构重建。

正式批量制作前，先完成封面、代表性方法页和结果页及对应口播，并与实际参考页并排查看：逐项核对图文比例、层次、阅读顺序及需要调整的对象；指出模板结构具体体现在哪里。对照原文和口播，检查听众能否从页面找到关键对象、跟上方法为什么有效，以及根据具体比较读出结果；删除口播中妨碍理解的制作核查细节。发现机制讲不通、证据看不清或模板结构没有落地时先修改，再继续制作。此关口需要实际阅读和视觉判断，不能凭自动导出、标题存在或对象可编辑判定通过；检索结果只供候选选择。

## 3. 图表、图片与公式

图形按charts-and-assets.md区分论文原图、Image2生成插图与定量数据；不得用生成图改造实验数据，也不能忽略用户的Image2要求。科研数据需要额外绘图时，按该文件确定用户授权后可用的绘图路径。原生Chart/Table按上游`references/native-data-interface.md`及`scripts/docs/native-data.md`验证，不夸大编辑能力。

图片通过可用搜索工具或后端image-search查找，实际查看并登记来源与复用依据，再下载和裁剪；用户提供图片同样确认用途。检索无结果时更换查询或使用准确示意，不将缺图留成占位符。背景服务阅读，数据页不强加装饰图。

公式使用上游`references/native-formula.md`的LaTeX与OMML协议；编译前核对符号和数学含义。PowerPoint原生公式与WPS显示分别检查，上游声明WPS可能使用预览回退，不能把PowerPoint可编辑性无条件套到WPS。

## 4. 页面制作和讲稿

默认按visible-authoring.md在前台WPS逐页制作，先完成代表性正文页并实际查看，再继续其余页。只有当次明确指定后台SVG整稿时才改走svg-pipeline.md。普通文字、图示与表格按关系组织；不复制单一模板，不把所有内容都压成几个词。

完整论文汇报默认逐页讲稿；当次明确不需要或仅请求局部/分析时按实际范围执行。默认notes=false，逐页口播写入独立讲稿，不写入PPT备注；仅用户当次明确要求备注时才启用notes。根据最终页面写逐页讲稿，解释为什么做、如何读图、发现和前后衔接，不重复堆叠页面文字，不包含工具、检索、选图或验收过程。图旁保留可见原图图号与简短来源；详细定位可另置备注资料区，不混入口头讲稿。如当次明确要求写入备注，再核对原生备注与独立讲稿的一致性。

## 5. 检查、导出和交付

WPS工程使用authoring_mode=wps、presentation和各页slide字段，以实际PPT为内容权威。完整新稿在制作前建立按叙事顺序排列的页面清单；试排页可先制作，但整合后必须核对保存文件的每页标题与顺序、独立讲稿，以及当次要求的备注，不能以预定顺序代替实际文件。使用expected_title和research_deck.py check辅助定位页序、来源及备注问题；人工复核标题语义与页面内容。仅SVG整稿路线运行SVG final检查。原生图表额外核对数据、标注与预览一致性，不能只用哈希代替语义检查。

逐页制作期间即在前台WPS检查，并在保存后复查最终文件。确认字体、公式回退、表格、裁剪及独立对象；全稿缩略图检查版式节奏，逐页检查机制和证据是否完整。`research_deck.py checkpoint <project>`只记录当前输入指纹，不会授权或刷新视觉审核。实际逐页查看当前版本后，显式运行`research_deck.py review-visual <project> --reviewed`记录当时的输入指纹；随后`check`只在内容与该审核指纹一致时显示passed。内容变化后即使反复checkpoint也保持pending，须重新查看并显式登记。旧清单的visual_review字段和旧checkpoint不自动继承通过状态。此记录是执行者声明，不是工具证明已人工查看，更不代表科研内容正确。

## 6. 修改、续作和维护

续作先读工程清单、设计记录、最终文件与输入指纹。check报告变化时，定位受影响页面，重作图表或讲稿并重新检查。checkpoint表示保存当前状态，不是视觉验收证书。

既有PPT修改默认在前台WPS当前页进行；用户当次明确指定SVG往返时用后端import-pptx并读取上游`workflows/edit-native-pptx.md`，保留原文件、导入工作区及映射；禁止将WPS修改稿被旧SVG覆盖。无需无关重做。

依赖或网络失败时报告实际失败模块，继续不依赖它的工作。动画、音频、自动播放仅在用户要求时启用，先读[可选演示能力](optional-delivery.md)，不成为科研汇报的默认门槛。

## 运行前检查

使用独立运行环境执行`scripts/presentation_preflight.py`检查当前路线依赖，默认--mode wps；明确使用SVG后端时选--mode svg，完整组件检查选--mode all。不要因可选SVG或音视频依赖缺失阻断普通前台PPT任务。通过表示本地依赖齐备；网络、目标应用和最终内容仍在实际使用时验证。不得将预检结果复制进汇报正文。

## 科研页面内容要求

按论文类型选页面角色，不要求每篇全部出现，也不固定页数。

| 页面任务 | 必须支撑的信息 | 合适的表达 |
|---|---|---|
| 问题与动机 | 具体对象、现有方法的实际缺口 | 场景图＋问题定位 |
| 方法与机制 | 输入、关键操作、输出及因果关系 | 流程、架构、时序、算法片段 |
| 理论与公式 | 符号含义、推导关键步骤、必要假设 | 公式＋图解或简例 |
| 实验设置 | 仿真或实测、设备/软件、参数、数据、基线、指标 | 参数表＋实验结构图 |
| 实验结果 | 比较对象、量纲、样本/重复与误差含义、实际发现 | 主图＋读图标注＋具体结论 |
| 消融与敏感性 | 改动变量、控制变量与性能变化 | 分组对比、趋势或热力图 |
| 讨论与结论 | 贡献、机制解释、具体未解决问题 | 证据对应的结论与研究问题 |

正文页应有足够证据解释标题，不能只剩一句结论和几个空卡片；缺信息时回到原文查找，不能编造数据填满页面。方法页检查机制是否可讲清，结果页检查读者是否能从图中读出发现。必要时合并稀疏页或把过密页分成有因果衔接的页面。

图片参考先提炼配色、字体、栅格和页面角色，再用不同密度的内容检查适配。只得到截图不等于得到原生母版；只安装Style不等于安装Layout。网络模板需实际预览正文页，不能只凭封面选用。

真实科研论证可以进入正文；助手的选图理由、工具步骤、自检清单、任务规划不得进入正文或备注。自动短语检查仅提示复核，不能替代逐页阅读，也不能机械删除科学成立条件。

汇报时长已知时按页面讲述任务分配时长，重点给方法与证据；讲稿随最终页序检查一次。附录、备份页、PDF、录音或自动播放仅按需求生成。交付说明简述文件、实际编辑方式与未解决的具体问题，不把内部测试文件混入正式材料。

## 防止模板理解与页面执行脱节

用户提供模板或认可一组页面时，先实际查看有代表性的封面、方法页和结果页，记录各自的信息块、相对尺寸、对齐、图注和阅读顺序；制作前把本稿代表页的内容与参考页逐块对照，而不是仅继承颜色和标题栏。以最终实际渲染页面检查这些关系是否落地，内容不适合时明确调整，不强套原页。把参考页中的真实对象或区域及相对位置落实为本次逐页版式依据：列出标题、图、文字、公式、图注各自的区域与阅读顺序；有可编辑源模板且适配时，可保留其原生结构并按本次内容调整。需要自行设计时先形成可检查的逐页构图；用户指定图片先行或该方式更适合时，可先制作视觉稿再重建，无需为已授权的中间步骤反复询问。用户直接要求PPT时，不强制每次生成整页图片。无论哪条路径，都应保存对应参考和最终页，逐页比较后纠正；不得把整页图放进PPT冒充可编辑页面，也不将一次视觉稿当作今后所有任务的固定模板。

用户要求图像一比一且完全可编辑时，先逐项区分可编辑文本、图形、表格、数据图和原始品牌图。对论文曲线、轮廓化文字等先验证可用的数据或矢量来源，真实说明对象级编辑程度和视觉误差；无法同时满足的部分标明并继续完成不依赖它的工作，不凭可移动的整张图片或透明文字宣称全部可编辑，也不承诺未经验证的像素一致。每页建立最终视觉稿与重建页的对应关系，渲染当前保存文件逐页比较；任一方变更后重新检查对应页。

论文矢量图遇到不支持的组裁剪时，不能直接删除裁剪以通过转换：先在副本中分析裁剪、变换、填充规则、描边和图层，再以可靠的几何转换或逐项重建生成候选。像素比对前先用实际会改变画面的裁剪样例验证渲染器确实支持裁剪；以多个分辨率比较完整候选与原图，并在目标 WPS／PowerPoint 中重新查看，检查曲线、柱形、边缘和相互遮挡。虚线、多段线型、字体、路径空洞等可能被转换器简化，也应检查，不以转换器通过作为视觉正确的证明。实验性的特定图处理脚本不能宣传为适用于任意 SVG 的通用转换器。

实际操作验证需区分：形状可拆组和移动、文字可直接输入编辑、以及图表可通过数据表修改数值。轮廓化字形只是形状；将其恢复为文字需逐项核对原文、字体和位置。原始数据不可得时不从截图猜测精确数值并伪装成原生数据图；用户要求内部全部可编辑时，记录尚未满足的对象，继续处理并在交付前进行对应编辑验证。

### 图像参考的逐页执行与矢量复用

用户认可图片稿或明确要求照图重建时，图片是该次页面的构图依据：制作当前页前核对标题、正文、图注、论文图和装饰的相对大小、边距、对齐、层次和阅读顺序；同时检查研究表述和听众理解，不得只取配色或用旧版式替换。现有合适模板可以整套使用；只有内容确需时才适度组合。完成一页后用WPS实际导出与参考逐页比对，记录仍有差异的内容，下一页复用已验证的通用操作而非上一稿的研究内容。

论文图优先寻找原始数据或PDF中的真实矢量。对于以路径保存的文字，先逐项核对原图文字及位置，再恢复可输入文本；图例、刻度、单位和曲线不得由图像模型臆造。先做一个面板的裁剪、字体和WPS编辑验证，同文档同类图可复用已验证的处理工具和参数，但仍逐面板核查字形映射、图层、数据与显示，禁止把某个成功案例当作通用一键保证。自动检查通过不等于WPS视觉一致或数据可用。
